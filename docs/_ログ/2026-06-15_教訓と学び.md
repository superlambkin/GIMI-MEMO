## 教訓 1: Compose の `LaunchedEffect` の key は固定値にせよ

### 何が起きたか
`LaunchedEffect(System.currentTimeMillis())` が **毎回再実行** されてしまい、stop → 次画面遷移バグの原因に。

### 教訓
- **key には「再実行したい条件が変わる瞬間」だけを渡す**
- 「初回 1 回だけ」 = `LaunchedEffect(Unit)`
- 「特定 state 変化で」 = `LaunchedEffect(state)`
- ❌ `System.currentTimeMillis()` / `Random.nextInt()` / `Date()` のような **毎回違う値** は絶対 NG
- ✅ unit test で「key の安定性」を疑う習慣をつける

## 教訓 2: OpenAI 互換 ≠ OpenAI 互換 (input_audio 周り)

### 何が起きたか
OpenAI 互換を謳う MiniMax / DeepSeek / Claude 等の API で `input_audio` (audio base64) フィールドの扱いがバラバラ。Gmail で MIME=application/octet-stream だと添付扱いされない。Gmail 直起動 vs Chooser 起動で挙動が違う。

### 教訓
- **サードパーティ LLM の音声サポートは要 Web 確認**
- 公式に「input_audio サポート」と書かれていても、MIME 形式や base64 エンコード要件が違うことがある
- 当面ミニマム互換セット: `type=message/rfc822` + `setSelector(mailto:)` + `EXTRA_EMAIL` + `EXTRA_STREAM` (FileProvider URI) + `ClipData` での grant
- フォールバック戦略を 3 段階 (直起動 → Chooser → mailto 添付なし) で持つ

## 教訓 3: 端末依存コードは ADB テスト限界を知る

### 何が起きたか
Mi Note 10 Pro + MIUI 環境で `adb input tap` の座標精度が低く、設定画面奥のボタンをタップできなかった。`uiautomator dump` も MIUI テーマと相性悪い。

### 教訓
- **Compose UI テストは Espresso + `createComposeRule()` が正攻法**
- ADB 経由は smoke test のみ、本番は手動 or instrumented test
- テスト容易性のため **Navigation に deep link を追加** しておく
- screencap 取得 + 手動目視は最終手段だが現実的

## 教訓 4: Compose の `var text by remember` は source of truth 問題

### 何が起きたか
`OutlinedTextField` の値を local `var text` で持つと、再コンポーズ時に `initialValue` で上書きされ IME カーソル消滅。

### 教訓
- フォーム入力は **必ず ViewModel StateFlow を SoT にする**
- Composable 側は `value = ` で読み、`onValueChange` で更新だけ
- 6 プロバイダ全部で起こるので、テンプレ化して必ず従う

## 教訓 5: Hilt cross-module 依存は手動 `@Provides` で OK

### 何が起きたか
`OnDeviceWhisperClient` を `@Inject constructor` で宣言したら、cross-module metadata 生成でビルド失敗。`@Provides` に変更したら解決。

### 教訓
- 別 module の class を Hilt で inject する場合は `HiltModule` で `@Provides` を明示
- `@Inject constructor` の方が綺麗だが、cross-module で失敗したら `@Provides` に逃げる
- 依存方向を一方向 (app → core-llm → core-whisper) に揃えると事故が減る

## 教訓 6: 「ユーザーへの確認」は臆せず行う

### 何が起きたか
mini モデルに切替を「勝手に」提案した場面、ユーザーは精度優先で base 維持を希望。`CLAUDE.md` の「**安全優先**」「**推測ではなく確認**」原則を遵守すべきだった。

### 教訓
- 性能改善は UX 影響が大きい → 必ず「コスト (精度劣化) vs ベネフィット (速度)」を比較提示
- 「tiny に切替えますか?」と聞いたら「base 維持で」と即答
- **仮定を置かず選択肢を提示する** 原則を忘れない

## 教訓 7: MultiAgent 体制は並列化できるが、contention が出ないように分解

### 何が起きたか
- 大雄調研 → 小夫編程 → 静香測試 の 3 段階が綺麗に連携して回った
- ただし子 Agent は別セッションになるため、**context は本セッションで再読込必須**

### 教訓
- **並列可能な調査タスクは並列に投げる** (例: メール共有調査 + 言語ヒント調査を同時並列)
- **コード修正 / ビルド / 実機テストは直列** にする (context がシリアルに必要)
- Goal-A〜F のように **段階目標 + 担当 Agent 役割** を最初に決めると効率的
- 子 Agent が CLAUDE.md を読むように依頼すると、プロジェクト規約準拠率を保てる

## 教訓 8: 実機 ADB の座標と Compose のレイアウト差異

### 何が起きたか
- `adb input tap` で Y 座標 200 を指定したが、Compose の Button は Y=180 を中心に ±30 程度
- 隣接要素のボタンが誤って押されがち
- 一度タップで意図しない Activity が前面に出て復帰できない

### 教訓
- **Compose は HitTestBox を厳密に確認**
- ADB 経由より **`am start` で DeepLink 起動** の方が信頼性高い
- 一度失敗したら **`am force-stop <pkg>` で確実に初期化** してから再試行

## 教訓 9: リリース APK 命名規則を統一する

### 教訓
- ファイル名: `GijiMemo-v{versionName}-{buildType}-YYYYMMDD_HHmmss.apk`
- 例: `GijiMemo-v0.3.1-release-unsigned-20260615_193813.apk`
- バージョン名・ビルドタイプ・タイムスタンプを含むことで、複数 APK の一意性確保

## 教訓 10: オンデバイスリアルタイム文字起こしは現世代端末では非現実的

### 何が起きたか
- v0.7.7 で録音中のリアルタイム文字起こし（ストリーミング）機能を全レイヤー実装
- medium model (514MB) → 1.5秒窓の処理に15秒以上かかり追いつかない
- tiny model (31MB) → 処理速度は十分だが精度不足で空セグメントが頻発
- クラウド API (OpenAI Whisper) → 7秒バッファリング + ネットワーク送信でレイテンシ大・コスト増
- 結果: **全方式とも実用レベルに達せず、v0.7.8でストリーミング計画を中止**

### 教訓
- **端末内 LLM/ASR の処理速度は楽観的に見積もらない**
  - デスクトップ GPU 環境とモバイル CPU 環境では 10〜50倍の速度差がある
  - "medium モデルでも何とかなる" は楽観的すぎた → 実機検証後に判断すべき
- **tiny モデルの精度は「聞き取れたふり」をするレベル**
  - 無音区間でも断片的なテキストを返すことがあり、ユーザー体験を損ねる
  - 「速度が足りない」と「精度が足りない」の板挟み
- **クラウド API をストリーミング代わりに使うのは設計として不適切**
  - 7秒バッファなら「リアルタイム」ではない
  - コスト: 7秒ごとの API 呼び出しは従量課金が跳ね上がる
  - レイテンシ: オンデバイスの利点（即時性・オフライン）を捨てるなら、録音後の全文字起こしで十分
- **"まず動かしてみる" より "まず速度見積もり" を先にやるべきだった**
  - 実装前に medium model の推論時間を測定していれば、全レイヤー書く前に中止判断できた
  - 次回: 「この端末で N秒の音声処理に何秒かかるか」を真っ先に計測する

### 今後の方針
- 録音中のプレビュー表示は諦め、録音後の全文字起こし（StoppedPlayback → Processing）に集中
- 端末性能が向上した将来、または NPU 対応モデルが登場した際に再検討
- 代替: ProcessingScreen の文字起こし進捗表示（ドーナツチャート + 経過時間）を改良してユーザー待機体験を改善
