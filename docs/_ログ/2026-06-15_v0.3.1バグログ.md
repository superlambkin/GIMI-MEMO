## Bug #1: 録音画面遷移後、再生/文字起こし画面に前進できない

**重大度**: HIGH (コア機能停止)  
**報告日**: 2026-06-14 朝  
**報告者**: ユーザー Hori

### 症状
「停止して保存」を押下しても、停止後 UI が「録音開始」ボタンに戻ってしまう。録音 → 停止 → 文字起こし への前進が不能。

### 原因
`RecordingScreen.kt` の `LaunchedEffect(System.currentTimeMillis())` で `_lastSavedSession` を毎再コンポーズで `resetLastSavedSession()` → 常に Idle 表示に戻る。

```kotlin
// ❌ BAD: 再コンポーズごとに key が変わる
LaunchedEffect(System.currentTimeMillis()) {
    elapsedMs = 0L
    viewModel.resetLastSavedSession()  // 毎フレーム実行
}
```

### 修正
`LaunchedEffect(Unit)` に変更し、リセット責務を `LaunchedEffect(state)` に分離。

```kotlin
// ✅ GOOD: 初回 1 回だけ実行
LaunchedEffect(Unit) { elapsedMs = 0L }
LaunchedEffect(state) {
    if (state == RecordingState.Recording) viewModel.resetLastSavedSession()
}
```

### 検証
実機 (Mi Note 10 Pro) で「停止して保存」後に「日本語」「中国語」「キャンセル」ボタンが表示されることを確認 ✅

## Bug #2: 録音後タイマーが 00:00 で固定表示

**重大度**: MED  
**報告日**: 2026-06-14  
**報告者**: ユーザー Hori

### 症状
録音停止後、表示時刻が「00:00」のまま固まる (実録音が数秒でも「00:00」と表示)。

### 原因
`RecordingScreen.kt` のタイマー `LaunchedEffect(Unit)` で、`state != Recording` のとき `elapsedMs = 0L` にリセットしていた。

### 修正
`lastSavedSession.durationMs` を参照する条件分岐を追加。

```kotlin
elapsedMs = when {
    start != null && state == RecordingState.Recording ->
        System.currentTimeMillis() - start
    lastSavedSession != null -> lastSavedSession?.durationMs ?: 0L  // 修正
    else -> 0L
}
```

### 検証
録音 8 秒 → 停止後 8 秒のまま表示継続 ✅

## Bug #3: メール共有でメーラーは起動するが宛先/添付が空

**重大度**: HIGH (共有機能の核)  
**報告日**: 2026-06-14  
**報告者**: ユーザー Hori

### 症状
- プレビュー画面で「メールで共有」→ メーラーは起動
- 起動したメーラーの **To: 欄が空**
- **添付ファイル (.docx/.md/.txt) もない**

### 原因 (3 回の変遷)

| 試行 | 修正 | 結果 |
|---|---|---|
| v0.2.0 | `Intent.ACTION_SEND` + `type="*/*"` | MIME 曖昧でメーラー候補から除外される |
| v0.3.0 一回目 | `setSelector(Intent(ACTION_SENDTO, mailto:))` | Gmail/MIUI で EXTRA_EMAIL を破棄、Chooser 連携も壊れる |
| v0.3.0 二回目 | setSelector 撤廃 + ClipData grant | 宛先なしで再発生 (ChatGPT が前面に) |
| **v0.3.1 最終版** | `setSelector(mailto)` 復活 + MIME=message/rfc822 | 検証待ち |

### 最終コード
```kotlin
val attachmentMime = "message/rfc822"
val mailtoSelector = Intent(Intent.ACTION_SENDTO, Uri.parse("mailto:"))

Intent(Intent.ACTION_SEND).apply {
    type = attachmentMime
    selector = mailtoSelector
    putExtra(Intent.EXTRA_EMAIL, arrayOf(recipient))
    putExtra(Intent.EXTRA_SUBJECT, subject)
    putExtra(Intent.EXTRA_TEXT, body)
    putExtra(Intent.EXTRA_STREAM, fileProviderUri)
    clipData = ClipData.newUri(...)
    addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
}
```

### 副次対応
- `<queries>` 宣言追加 (API 30+ Package Visibility 対応)
- `recipient` 空文字チェック
- フォールバック: 3 段階 (Gmail 直起動 → Chooser → mailto: 添付なし)

### 検証
**v0.3.1 で実機検証待ち** (ADB 経由では Gmail 認証フロー必要)

## Bug #4: 文字起こし結果に LLM 内部の思考が混入

**重大度**: MED (UX 品質)  
**報告日**: 2026-06-14  
**報告者**: ユーザー Hori

### 症状
MiniMax M3 / DeepSeek R1 などの reasoning モデルが `<think>...</think>` を要約内に出力してしまう。

### 修正
`ProcessingViewModel.stripThinkTags()` を追加し、`LlmEvent.Complete` 時点で除去:

```kotlin
private fun stripThinkTags(text: String): String {
    var s = text
    s = Regex("(?is)<think(?:ing)?>.*?</think(?:ing)?>").replace(s, "")
    s = Regex("(?is)```\\s*think(?:ing)?\\b.*?```").replace(s, "")
    s = Regex("(?is)<think(?:ing)?>.*$").replace(s, "")
    return s.trim()
}
```

### 検証
v0.3.0 で MiniMax 利用時に混入解消 ✅

## Bug #5: 中国語ボタンが効かない (日本語と判定される)

**重大度**: HIGH (言語機能)  
**報告日**: 2026-06-14  
**報告者**: ユーザー Hori

### 症状
中国語録音を「中国語」ボタンで転写 → 結果が日本語で返る。

### 原因 (二重バグ)

1. **JNI ハードコード**: `whisper_jni.c:72` で `params.language = "ja"` 固定 → 中国語音声が日本語としてデコード
2. **キャッシュ未使用**: `ProcessingViewModel.runSinglePhase(audio, prompt, ...)` で `cachedPrompt` ではなく `prompt` を渡していた → 言語ヒントが破棄

### 修正

**JNI 側** (`whisper_jni.c`):
```c
const char *language = NULL;  // ハードコード撤廃
if (language_str != NULL) {
    language = (*env)->GetStringUTFChars(env, language_str, NULL);
}
params.language = language;  // NULL → 自動検出
```

**ViewModel 側**:
```kotlin
// ✅ FIXED
runSinglePhase(audioFile, cachedPrompt, LlmCallMode.MULTIMODAL)
```

### 検証
中国語ボタン → 中国語転写結果 ✅ (実機)

## Bug #6: OnDevice Whisper OFF で「モデル読み込み中」表示

**重大度**: MED (UX 誤誘導)  
**報告日**: 2026-06-14  
**報告者**: ユーザー Hori

### 症状
OnDevice Whisper = OFF なのに処理画面で「ローカル Whisper モデル (tiny, 75MB) を読み込み中...」が表示される。

### 原因
`ProcessingScreen.kt:TranscribingContent` が `elapsedSec` だけでメッセージ切替し、`useOnDevice` を考慮していなかった。

### 修正
`ProcessingState.useOnDevice: Boolean` を追加し、Composable 側で分岐:

```kotlin
val phaseMessage = when {
    useOnDevice && elapsedSec < 3 -> "音声ファイルを読み込み中..."
    useOnDevice && elapsedSec < 30 -> "ローカル Whisper モデル (base, 141MB) を読み込み中..."
    useOnDevice -> "文字起こし中..."
    elapsedSec < 3 -> "音声ファイルを送信中..."
    else -> "クラウドで文字起こし中..."
}
```

### 検証
ON/OFF 両方とも文言正しく ✅

## Bug #8: ApiKeyManagementScreen 入力途中で IME が消える

**重大度**: MED  
**報告日**: 2026-06-15  
**発見者**: 自前 Code Review

### 症状
長い Key を貼り付け中に再コンポーズが走ると、IME 状態と入力途中のカーソル位置がリセットされる。

### 原因
```kotlin
// ❌ BAD: Composable の local 状態が source of truth
var text by remember { mutableStateOf(initialValue) }
```

```kotlin
// ✅ GOOD
val currentValue = draftMap[provider.apiKeyRef].orEmpty()
OutlinedTextField(
    value = currentValue,
    onValueChange = onValueChange,
    ...
)
```

## Bug #9: テスト 5 件が ClassCastException

**重大度**: MED (テストインフラ)  
**報告日**: 2026-06-15  
**発見者**: 自動回帰テスト

### 症状
`ProcessingViewModelTest` 実行時に `Object cannot be cast to String at ProcessingViewModel.kt:67`

### 原因
`SavedStateHandle.get<String>("lang")` 呼び出しに対し、テストの `mockSavedStateHandle()` で `lang` キーのモックを追加していなかった。

### 修正
```kotlin
private fun mockSavedStateHandle(): SavedStateHandle {
    val handle = mockk<SavedStateHandle>(relaxed = true)
    every { handle.get<String>("sessionId") } returns "session-1"
    every { handle.get<String>("lang") } returns ""  // ← 追加
    return handle
}
```
