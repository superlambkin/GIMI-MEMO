## 問題 #1: 実機 ADB 経由の Compose ボタンタップ精度が低い

**影響**: 自動回帰テストでの実機操作が困難  
**原因**: ターゲット座標が Compose のヒット領域と一致しない、MIUI のジェスチャ操作と干渉

### 回避策

#### A. 開発者向け (ADB ユーザー)

| ケース | コマンド例 |
|---|---|
| Activity 強制起動 | `adb shell am force-stop <pkg>` + `monkey -p <pkg> 1` |
| 特定座標タップ | `adb shell input tap X Y` (座標は手動推定) |
| スクリーンショット取得 | `adb exec-out screencap -p > screen.png` |
| uiautomator dump | MIUI で失敗する場合あり → screencap で代替 |

#### B. 将来の改善

- **Deep link を Navigation に追加** → `app://api-key-management` で直接遷移可能化
- **Espresso UI テスト** を `androidTest` に追加して ADB タップの精度問題を回避
- **Compose テスト** (`createComposeRule`) で unit test 可能な Composable に切り出し

## 問題 #2: リリース APK が未署名

**影響**: Play Store 公開不可、実機インストール不可 (debug 用は OK)  
**原因**: 署名鍵未設定

### 回避策

- **デバッグ用**: `app-debug.apk` をそのまま使う (検証目的)
- **配布用**: 署名鍵を生成し `app/build.gradle.kts` の `signingConfigs` を設定

```kotlin
signingConfigs {
    create("release") {
        storeFile = file("release.keystore")
        storePassword = ...
        keyAlias = "..."
        keyPassword = ...
    }
}
buildTypes {
    release {
        signingConfig = signingConfigs.getByName("release")
        isMinifyEnabled = true
    }
}
```

## 問題 #3: claude-mem プラグイン hook エラー (環境)

**影響**: claude-mem worker unreachable で hook が繰り返し失敗  
**原因**: プラグイン worker プロセスとの接続不可 (環境依存、観測範囲)

### 回避策

- hook 失敗は無視して続行 (本セッションでは実害なし)
- 必要なら `~/.claude/plugins/cache/thedotmack/claude-mem` を確認
- 代替: 手動で memory ファイル (`MEMORY.md`) に書き込む

## 問題 #4: WebSearch API 制限 (一時的)

**影響**: 検索結果が返らない (`400 invalid params`)  
**原因**: 一時的な API 制限

### 回避策

- リトライ + 待機
- 代替: WebFetch で特定 URL を直接取得
- 知識ベースの情報を活用

## 問題 #5: Git Bash `/tmp` ディレクトリが Read ツールから不可視

**影響**: スクショや一時ファイルが Read できない  
**原因**: Git Bash の `/tmp` は MSYS 仮想領域、Read は Windows パスを要求

### 回避策

```bash
# 回避: 一時ファイルを Windows パスにコピー
cp /tmp/foo.png "C:/Users/superlambkin/Desktop/foo.png"
```

## 問題 #6: Compose で `var text by remember` の罠

**影響**: 入力途中の IME / カーソル位置がリセット  
**原因**: 再コンポーズ時に local state が `initialValue` で上書きされる

### 回避策

- Single source of truth を ViewModel の StateFlow に集約
- Composable では `value =` で参照のみ、`onValueChange` でのみ更新

---

## 問題 #7: Room DB v1→v2 migration 破壊的

**影響**: v0.3.0 → v0.3.1 で既存セッション消失  
**原因**: `processingDurationMs` 追加、`fallbackToDestructiveMigration` 採用

### 回避策

- debug ビルドで許容
- リリースでは `Migration` クラスで `ALTER TABLE sessions ADD COLUMN processingDurationMs LONG NOT NULL DEFAULT 0` を実行

---

## 問題 #8: 古い APK がデスクトップに蓄積

**影響**: ディスク使用量増、探すのが困難  
**原因**: バージョン毎に APK 保存

### 回避策

- 最新 2 個だけ残して古い APK を削除
- `GijiMemo-v0.3.0-*` 4 個を削除候補
